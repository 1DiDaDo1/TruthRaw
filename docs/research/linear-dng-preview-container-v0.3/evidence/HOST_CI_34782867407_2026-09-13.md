## Preserved failed precursor run

The immediately preceding run `34782751554` is intentionally preserved as failure evidence.

In that run:

- Clang Release passed;
- Clang ASan/UBSan test passed;
- GCC compiled successfully but the test failed while reading `PreviewApplicationName`.

Cause: C++ function-argument evaluation order around `vector.size()` and `std::move(vector)` made the TIFF ASCII count compiler-dependent.

The writer was fixed, not the regression assertion: ASCII TIFF count is now derived from the payload after it is received by the entry helper. Run `34782867407` proves the corrected behavior across GCC, Clang and sanitizers.

## Scope

This is host/container proof only. It does not prove:

- Android/JNI integration of v0.3;
- that an Android `Bitmap.compress()` JPEG is accepted by the v0.3 JPEG parser;
- physical Honor execution;
- Android/piex preview discovery;
- Lightroom/ACR behavior;
- LibRaw or Adobe DNG SDK validation of a newly produced v0.3 DNG.

Those remain independent gates.
